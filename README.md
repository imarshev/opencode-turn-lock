# opencode-turn-lock

[![tests](https://github.com/imarshev/opencode-turn-lock/actions/workflows/test.yml/badge.svg)](https://github.com/imarshev/opencode-turn-lock/actions/workflows/test.yml)

Плагин для **OpenCode V2**, который держит на локальном движке не больше N агентских сессий одновременно, а остальные ставит в очередь на уровне модели — и говорит сессии, что она ждёт.

> **EN.** An OpenCode V2 plugin that serialises agent *turns* against a local model engine: at most N sessions may call the local model, everyone else waits before the request is sent. Cloud providers are never gated, subagents inherit their parent's verdict, and a queued session gets an in-transcript notice with the queue state. Leases survive across plugin instances (per-location) and processes, are refreshed by a heartbeat, and are released on every terminal event of a turn.

---

## Кому и зачем

**Нужен, если** у вас локальная модель и несколько сессий OpenCode:

- движок обслуживает **один запрос за раз** (llama.cpp, `strata`, любой сервер с `serving=1`);
- вы держите открытыми 2–5 сессий (TUI, web, субагенты) и они «параллельно» работают над разными задачами;
- у движка есть **кэш контекста** (park/restore), и переключение между сессиями стоит дорого.

**Проблема без плагина.** OpenCode не синхронизирует сессии: каждая шлёт запрос, когда захочет. Движок выстраивает их в FIFO, но приоритетов не имеет, поэтому две сессии агента буквально чередуются шаг за шагом. Каждое переключение — парковка контекста прошлой сессии и восстановление нового. Когда бюджет кэша кончился, каждая смена — полный префилл.

Замер на этой машине (локальный движок, 6 слотов кэша / 10 ГиБ, 4,7 часа работы): **206 вытеснений**, кэш упирался в 9,87 ГиБ из 10 240 МиБ, пример промаха — **55 042 токена префилла, 22,1 с** ожидания. Причина — не модель и не железо, а именно чередование сессий.

**Плагин меняет порядок:** сессия получает слот на весь свой ход и держит его, пока ход не закончится (или агент не задаст вопрос / не попросит разрешение). Вторая сессия работает параллельно, третья ждёт — и уходит в модель только когда слот освободился.

**Не нужен, если:** все сессии на облачных моделях; у вас один движок на сессию; сервер умеет батчинг и переключение контекста вам не мешает; вы и так работаете в одной сессии.

## Что делает

| | |
|---|---|
| **Лимит** | не больше `limit` (по умолчанию 2) локальных сессий одновременно |
| **Гранулярность** | слот на **ход** (turn), а не на вызов модели: одна сессия не вытесняет сама себя между шагами |
| **Облако** | не гейтится никогда: провайдер определяется по id (`strata`) или по loopback-`baseURL` |
| **Субагенты** | не занимают слот: наследуют решение родителя (`covered` / `exempt`) |
| **Уведомление** | ожидающая сессия получает сообщение в свой транскрипт: кто занял слоты и сколько держит |
| **Тайм-аут** | 4 часа ожидания (настраивается), дальше — `proceed` сверх лимита или `hold` |
| **Отказоустойчивость** | heartbeat, stale-лизаренс, boot-cleanup по мёртвому pid, fail-open на любых ошибках |
| **Служебные вызовы** | `title`, `compaction`/`summary`, `generate` не гейтятся вообще |

## Как это работает

```
сессия A (локальная) ──┐
сессия B (локальная) ──┤  context hook  ──►  lease (файл)  ──►  запрос в модель
сессия C (локальная) ──┘        │
                                └─ слотов нет → ждём, уведомляем, повторяем опрос

сессия D (облако)     ──────────►  hook вернулся сразу, лизаренса нет
субагент A            ──────────►  родитель держит слот → covered, слот не тратится
```

1. **Хук `context`** срабатывает прямо перед отправкой запроса в модель (включая продолжения после инструментов) и получает `sessionID` + `model.providerID`. Колбэк может быть асинхронным, поэтому запрос можно придержать.
2. **Провайдер.** `strata` из списка `localProviders` — локальный. Иначе плагин смотрит `settings.baseURL` провайдера: loopback-хост (`127.0.0.1`, `localhost`, `::1`, `0.0.0.0`, `127.x.x.x`) — локальный; всё остальное (включая неизвестный провайдер) — облако, хук выходит сразу.
3. **Лизаренс.** Локальная сессия пишет файл-лизаренс `<sessionID>.lease.json` в общий каталог и держит его до конца хода. Повторный вызов в том же ходе просто обновляет `seen`.
4. **Очередь.** Если живых лизаренсов уже `limit`, сессия опрашивает стор раз в секунду. Освободился слот — забирает. Каждый ждущий пишет лизаренс только после проверки, что после записи лимит не превышен (пост-проверка), а тай-брейк между процессами — по `since` с субмиллисекундным джиттером.
5. **Освобождение.** Слот снимается на любом терминальном событии хода (см. таблицу ниже). Плюс heartbeat обновляет `seen` каждые 20 с, stale-лизаренс без обновления 2 ч удаляется, а на старте плагин вычищает лизаренсы мёртвых процессов.
6. **Уведомление.** На первом ожидании сессия получает synthetic-сообщение в свой инбокс (`delivery: "queue"`, `resume: false` — не перебивает текущий шаг и не запускает новый прогон) и повторяет его каждые 5 минут, пока стоит в очереди.

### Почему файловый стор, а не память

OpenCode создаёт экземпляр плагина **на локацию** (рабочий каталог), а движок и поток событий — общие на сервер. Один и тот же лимит должен соблюдаться между локациями, поэтому лизаренсы лежат в каталоге `%TEMP%/opencode/turn-lock/` (или `$TMPDIR/...`, переопределяется `dir`). Один файл на сессию, запись атомарная (tmp + rename), чтение терпимое: битый файл считается отсутствующим.

### Освобождение слота

| Событие | Значение |
|---|---|
| `session.idle` | ход закончился |
| `session.status` (`status.type == "idle"`) | то же самое, но через статус |
| `session.execution.succeeded` / `.failed` / `.interrupted` | терминальный исход выполнения |
| `session.deleted`, `session.archived` | сессия исчезла |
| `session.inbox.cancelled` | запрос отменили в очереди |
| `form.created` | агент задал вопрос (ждёт человека) — `releaseOnForm` |
| `permission.asked` | агент просит разрешение — `releaseOnPermission` |

`busy`/`retry` в `session.status` слот **не** снимают.

## Установка

Требуется **OpenCode V2** (проверено на v2.2.2). Node нужен только для тестов.

### 1. Клонировать и указать путь

```powershell
git clone https://github.com/imarshev/opencode-turn-lock F:\Development\opencode-turn-lock
```

В `~/.config/opencode/opencode.json` (или `opencode.jsonc` проекта):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    { "package": "F:/Development/opencode-turn-lock" }
  ]
}
```

Локальный плагин-каталог OpenCode грузит через `package.json` → `exports` (`./src/index.ts`), собирать ничего не нужно. После изменения списка плагинов — `opencode reload` или перезапуск сервиса.

Опции можно задать прямо здесь:

```jsonc
{
  "plugins": [
    {
      "package": "F:/Development/opencode-turn-lock",
      "options": { "limit": 2, "notify": "all" }
    }
  ]
}
```

### 2. Проверить, что загрузился

Плагин пишет лог в `%TEMP%/opencode/turn-lock.log`:

```
INFO ready: limit=2 local=strata timeout=240min onTimeout=proceed notify=wait dir=... pruned=0
INFO wait ses_…: 2/2 local sessions are busy
INFO grant ses_… after 35s wait (held 1/2)
INFO subagent ses_…: exempt by ses_…      ← сабагент облачной сессии не ждал
```

Eсли строки `ready` нет — плагин не загрузился (проверьте путь в `plugins` и `opencode --log-level info --print-logs`).

## Конфигурация

Три уровня, побеждает последний: **дефолты → `~/.config/opencode/turn-lock.json` → `plugins[].options`**.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | выключить плагин, не убирая его из конфига |
| `limit` | `2` | сколько локальных сессий могут работать одновременно |
| `localProviders` | `["strata"]` | id провайдеров, которые считаются локальными |
| `localHosts` | `["127.0.0.1", "localhost", "::1", "[::1]", "0.0.0.0", "::", "[::]"]` | хосты `baseURL`, которые считаются локальными (плюс любой `127.x.x.x`) |
| `acquireTimeoutMs` | `14400000` (4 ч) | сколько ждать слот, прежде чем применить `onTimeout` |
| `onTimeout` | `"proceed"` | `proceed` — пойти сверх лимита (fail-open), `hold` — ждать дальше |
| `leaseTimeoutMs` | `7200000` (2 ч) | лизаренс без обновления `seen` считается брошенным |
| `pollMs` | `1000` | период опроса стора ожидающей сессией |
| `refreshEveryMs` | `20000` | heartbeat: как часто обновлять свои лизаренсы (0 — выключить) |
| `sweepMs` | `60000` | период уборки просроченных лизаренсов |
| `releaseOnForm` | `true` | снимать слот, когда агент задал вопрос (`form.created`) |
| `releaseOnPermission` | `true` | снимать слот на запрос разрешения (`permission.asked`) |
| `notify` | `"wait"` | `off` — без уведомлений, `wait` — только «стою в очереди», `all` — ещё и «слот получен» |
| `notifyEveryMs` | `30000` | не чаще одного уведомления об очереди на сессию за интервал |
| `remindEveryMs` | `300000` | повтор уведомления, пока сессия всё ещё ждёт (0 — не повторять) |
| `dir` | `%TEMP%/opencode/turn-lock` | каталог лизаренсов (общий для всех инстансов и процессов) |
| `logFile` | `%TEMP%/opencode/turn-lock.log` | лог; ротация на 2 МБ |
| `logLevel` | `"info"` | `off` / `info` / `debug` |

Пример `turn-lock.json` — в [`examples/turn-lock.json`](examples/turn-lock.json).

## Уведомление в сессии

Ожидающая сессия получает synthetic-сообщение в свой инбокс:

```
⏳ turn-lock: запрос стоит в очереди — занято 2 из 2 локальных слотов
   (ses_e58f…jWj1 — 12 с, ses_e592…5JLy — 21 с).
   Запрос уйдёт в модель автоматически, как только слот освободится.
```

Дальше — повтор каждые 5 минут («всё ещё в очереди (5 мин)»). При `notify: "all"` добавляется

```
▶ turn-lock: слот получен, запрос уходит в модель (ожидание 13 мин).
⚠ turn-lock: слот не освободился за 4 ч — отправляю запрос сверх лимита.
```

Сообщение ставится с `delivery: "queue"` и `resume: false`: оно не прерывает текущий шаг и не запускает новый прогон, а в историю модели попадает на следующей границе шага. Полностью отключается `"notify": "off"`.

## Наблюдаемость

- **Лог**: `%TEMP%/opencode/turn-lock.log` (уровень `debug` добавляет причины пропусков и lookup провайдеров).
- **Лизаренсы**: `%TEMP%/opencode/turn-lock/*.lease.json`, внутри `{ sid, since, seen, pid, owner, over? }`. `owner` — каталог локации, `pid` — процесс сервера.
- **Проверить очередь руками**:

```powershell
Get-Content "$env:TEMP\opencode\turn-lock\*.lease.json"
```

- **Инбокс сессии** (что именно увидит агент): `opencode api get /api/session/<sid>/inbox`.

## Ограничения и края

- **Строгого FIFO между ожидающими нет.** Они просыпаются на опрос (1 с), на практике выигрывает тот, кто ждёт дольше; гарантии порядка нет.
- **После тайм-аута лимит нарушается осознанно.** `onTimeout: "proceed"` — страховка от вечного дедлока: лучше третья сессия, чем молчание на 4 часа. Нужно строго — `"hold"` + `leaseTimeoutMs`.
- **Лимит общий на все локальные провайдеры** (один стор). Если поднимете второй локальный движок, лимит всё равно один — это осознанно: узкое место обычно машина, а не порт.
- **Hot reload плагина освобождает его лизаренсы** и они не восстанавливаются до следующего вызова модели этой сессией. Транзиентно, лечится следующим шагом агента.
- **Наследование субагентов опирается на `Session.Info.parentID`.** Сессия без `parentID` гейтится как корневая.
- **Хук `context` — только агентский цикл.** `title`, `compaction`/`summary`, `generate` намеренно не гейтятся: это короткие служебные вызовы, и задерживать их значило бы ломать облачные сессии.
- **Один запрос — один шаг.** Слот держится на весь ход, поэтому ход с длинными инструментами (сборка, тесты) занимает слот всё это время. Это и есть цель, но помните об этом, ставя `limit: 1`.
- **Windows/pid.** Boot-cleanup проверяет живость процесса через `process.kill(pid, 0)`; на Windows это поддерживается, но если сервер запущен под другим пользователем, ответ будет `EPERM` — лизаренс остаётся (и убирается по `leaseTimeoutMs`).

## Разработка

```
src/
  index.ts        плагин: конфиг, хук, события, уведомления, лог
  core.ts         чистое ядро: лизаренсы, acquire/refresh/release/cancel, sweep (без fs и без OpenCode)
  store-file.ts   файловый стор: атомарная запись, терпимое чтение, boot-cleanup
tests/
  core.test.ts    планировщик: лимит, тайм-ауты, stale, cancel, две «процесса» на одном сторе
  store.test.ts   файловый стор: round-trip, битые файлы, pruneDead, общий лимит
  plugin.test.ts  плагин целиком через фейковый ctx (хук, события, уведомления, субагенты)
  stubs/          заглушка @opencode/plugin для node --test
```

```powershell
npm test          # 35 тестов, Node >= 22.18 (type stripping, сборки нет)
```

Тесты плагина подменяют `@opencode/plugin` через `module.registerHooks` и гоняют настоящий `src/index.ts`: очередь, облачный bypass, все события освобождения, тайм-аут, heartbeat, boot-cleanup, уведомления. `memoryStore()` позволяет тестировать ядро без диска.

Добавить новое событие освобождения: строка в `RELEASE_EVENTS` + разбор `sessionID` в `eventSessionID` (если он лежит не в `data.sessionID`) + тест в `plugin.test.ts`.
