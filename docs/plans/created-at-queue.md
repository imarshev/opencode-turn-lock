# Очередь по абсолютному времени создания сессии

## Задача

Заменить сортировку очереди «билет хода + фора» на абсолютный `createdAt`
сессии и убрать 10-секундную фору. Лок отдаётся в момент старта инструментов, а
не на границе шага, чтобы не было гонки «шаг кончился — инструмент ещё не
пошёл».

Правила, которые должны выполняться:

1. Лок держит сессия (и её сабсессия) на время запроса к модели.
2. `step.ended` с `finish: "tool-calls"` не освобождает лок сразу: он
   освобождается на первом `session.tool.called` (или по таймауту
   `handoffMs`). `finish: "length"` держит лок до следующего `context`
   (продолжение) или `handoffMs`. Остальные `finish` освобождают сразу.
3. В очереди — только сессии, ждущие отправки запроса. Внутри уровня порядок
   по `session.time.created` (самая ранняя — первая), уровень (`⚡`/обычная/`▽`)
   старше возраста.

## Что удаляется

- `requeueGraceMs` и вся механика форы: `setGrace`, `readGraces`,
  `clearGrace`, `graceUntil`/`root` в билете, ветка форы в `holdsBack`.
- Билет хода `<sid>.turn.json` целиком: `readTicket`, `writeTicket`,
  `dropTicket`, `ticketSince`, `ticketTtlMs`, `TURN_END_EVENTS`.
  На boot остаётся только уборка осиротевших `*.turn.json`.

## Что добавляется

- `createdAt` из `info.time.created`, кэш `Map<sid, number>`; заполняется тем же
  `ctx.session.get`, что и `parentOf`.
- `createdAt` пишется в `*.wait.json`, чтобы другой инстанс (другая локация,
  тот же каталог состояния) видел возраст чужой сессии.
- `entryOf` берёт `createdAt ?? waited` (фолбэк — начало ожидания, если сервер
  не отдал `time.created`).
- `handoffMs` (по умолчанию 1000): сколько держать лок на границе шага, пока не
  начнётся инструмент или не придёт продолжение. `0` — отпускать сразу.
- `session.tool.called` в подписке; обработчик отпускает лиз, если для сессии
  взведён handoff.
- `step.ended` обрабатывает только инстанс, который взял лиз (`held.has(sid)`):
  поток событий серверный, и раньше соседний инстанс (другая локация) удалял
  чужой лиз на границе шага, обнуляя handoff. Терминальные события по-прежнему
  отпускают лиз безусловно — это уборка.

## Проверки

- `npm run check`, `npm test`, `npm run build`.
- Новые тесты: handoff до первого инструмента, `stop` отпускает сразу,
  `length` держит до продолжения, таймаут handoff, порядок по `createdAt`
  (в том числе «создана раньше, встала в очередь позже — всё равно первая»),
  `createdAt` в `*.wait.json`, «соседний инстанс не отпускает чужой лиз»
  (два инстанса на общем каталоге и общем потоке событий).
- Старые тесты про билет и фору переписать или удалить.

## Трасса решений (следующий шаг)

Проверка вживую показала, что человеческого лога не хватает: видно `release`,
но не видно, доставили ли событие, знал ли инстанс, что держит лиз, и почему
отпустил. Поэтому добавлен второй, машинный лог — `src/trace.ts`:

- `%TEMP%/opencode/turn-lock-trace/lock-YYYY-MM-DD.jsonl`, строка JSON на
  решение, файл на сутки, старые удаляются (`traceKeepMs`, по умолчанию сутки).
- Пишется всё, что нужно для разбора надёжности: `stream.open`/`stream.closed`
  (жив ли поток событий), `event.recv` (доставлено ли событие и что инстанс о
  нём думал), `event.ignore` (почему пропустил), `context.*` (какой путь в
  гейте), `acquire.*`/`lease.taken`/`wait`/`grant`/`timeout`, `step.handoff`/
  `handoff.arm`/`handoff.fire`/`tool.release`/`step.release`, `release` с
  `ageMs`, `stale`, `heartbeat`/`refresh`/`sweep`, `snapshot` раз в минуту
  (лизаренсы, очередь, `held`, `handoffs`, счётчик событий потока).
- Конфиг: `traceEnabled`, `traceDir`, `traceKeepMs`, `traceEveryMs`.
- Тесты: `tests/trace.test.ts` (JSON-строка, ротация по дню, retention,
  выключение) и три e2e-теста в `tests/plugin.test.ts` (гейт/шаг/отпускание,
  handoff и инструмент, соседний инстанс объясняет, почему не тронул лиз).
