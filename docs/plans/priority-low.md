# Доработка: три уровня приоритета очереди (низкий / обычный / высокий)

## Цель
Запросы сессий выстраиваются в очередь по приоритету: сначала ждущие с наивысшим,
затем с меньшим. Сейчас два уровня (обычный и `⚡` приоритет) — добавить «низкий».

## Решения (зафиксированы, спрашивать нечего)
- Уровни: `high` = `⚡` (обратно совместимо), `normal` (обычный, файла нет), `low` = `▽`.
- Ранг: high 2 > normal 1 > low 0. Отсутствие флага = normal.
- Флаг-сайдкар `<sid>.prio.json` получает поле `level` (`"high" | "low"`);
  файл без поля читается как `high` (старые файлы), `level:"normal"` = файла нет.
- Пуск слота: сессия берёт свободный слот, только если нет ждущего с **более высоким**
  рангом (внутри одного флага — по возрасту флага; обычный vs обычный — как раньше,
  кто раньше проснулся).
- Мягкая уступка: державший слот отпускает его на границе шага, если есть ждущий с
  более высоким рангом (низкий уступает обычному и высокому, обычный — высокому,
  высокий никому).
- Команда: `/prio on|high`, `/prio off|normal`, `/prio low`, `/prio` — переключает
  high↔normal (прежнее поведение).
- Пилюли (desktop + userscript): клик крутит цикл normal → high → low → normal.

## Критерий готовности
`npm test` зелёный; новый тест доказывает: low-ждущий идёт после обычных,
low-держащий уступает обычному ждущему, `/prio low` пишет флаг с level=low.
