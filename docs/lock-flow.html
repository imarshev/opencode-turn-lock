Почему так —

Правила, по которым это работает
1. Порядок очереди. Сначала уровень: ⚡ high → обычный → ▽ low. Внутри уровня: boost (тикет возврата поднят, раньше отпустил — раньше обслуживают), затем обычные, затем defer, затем по времени создания сессии.
2. Тикет возврата. Конец запроса с tool-calls/length пишет <sid>.turn.json с releasedGrants. Пока grants не вырос, сессия defer — не отбирает слот у очереди. После первой выдачи другому grants растёт, тикет «поднят» → boost.
3. Проверка перед взятием. holdsBack: (а) есть ждущий более высокого уровня → ждать; (б) тикет не поднят и есть не-defer ждущий → ждать; (в) FIFO-окно fifoGraceMs для мест впереди → ждать.
4. Параметры. limit=1, pollMs=200, fifoGraceMs=2000, returnTicketTtlMs=300000, acquireTimeoutMs=57600000 (16 ч, fail-open — аварийный клапан).
Симуляция повторяет логику src/priority.ts, src/tickets.ts и holdsBack/tryTake из src/index.ts и src/core.ts. Время ускорено: 1 тик = 200 мс модельного времени.
